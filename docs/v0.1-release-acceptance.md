## 2번의 잔여 — 컨테이너 안 실 토큰 Claude 세션

2b는 어댑터 충실성 + child span 기록이며 위 증거로 충족된다. 이와 **별개로**
FR-SBX-01의 "Claude 본체가 샌드박스 컨테이너 안에서 실행"은 다음 상태다:

- **기제는 배포 커널(Linux CI)에서 증명됨.** `t15-linux-gate` 5-attempt matrix
  (run 33894797227)가 무자격증명으로 관통: 컨테이너 안 Claude 기동·ProcessEndpoint
  stdio·overlay·egress·승인 relay·토큰 없는 인증 실패 `done{error}`·토큰 미유출.
- **미실행:** 실 토큰으로 인증된 Claude가 컨테이너 안에서 성공한 tool call을
  내는 끝-대-끝 한 장면. 하네스·runbook 완비(`t15_smoke_test.go`,
  `t15-smoke-runbook.md`)이나, 토큰(로컬)과 배포 커널(Linux)이 같은 머신에
  있어야 하고 이 조건이 현재 개발 환경에 없다.
- **macOS VM은 대표 실행 불가.** podman machine이 호스트 경로를 공유하지
  않아(MOUNTS:0) 바인드 마운트가 성립하지 않는다 — VERIFICATION이 아닌
  INFRASTRUCTURE 한계(`BLOCKED.md`). 또한 macOS VM은 배포 커널을 대표하지
  않으므로 제안서(§Q4)가 처음부터 보조 증거로 격하했다.

이 잔여는 **정상 사용자 환경(리눅스 호스트)에서 자연히 충족된다.** control
plane 조작은 어디서나(macOS 포함) 가능하고, 에이전트 격리 실행은 리눅스
호스트에서 한다 — 명세 §2의 control/execution plane 분리 그대로다.

## FR-SBX-04 스코프 — 문서화된 부분 충족

명세 소유자 [H]가 2026-09-04 수용: access token 발급자가 계정 전체 권한만
제공하여 "스코프를 좁힌"은 벤더 미지원이다. FR-SBX-04를 하향 개정하지 않고,
단기성·장기 자격증명 미반입은 충족(`t15_integration_test.go`·`local_test.go`),
스코프 축소는 스코프 토큰 발급 시 후속 작업으로 유지. API key/refresh
fallback 없음. 근거는 `docs/t10-scope-determination.md` §6.

## 결론

v0.1 릴리스 게이트 여덟 기준 중 **일곱은 완전 충족**, 2번의 컨테이너 안 실
토큰 부분은 **기제 증명 + 문서화된 실행 잔여**다. 잔여는 코드·설계 결함이
아니라 개발 환경(토큰과 배포 커널의 비공존)의 것이며, 리눅스 호스트를 가진
사용자·운영자가 `t15-smoke-runbook.md`로 해소한다.
