# 명세 변경 제안 기록

명세(docs/hx-기능명세서-v0.1.md)는 유일한 진실이므로 구현자가 직접 수정하지 않는다.
변경이 필요하다고 판단되면 여기에 제안만 기록하고, 명세 소유자의 승인 후 반영한다.

---

## SCP-001. §3.1 도식의 화살표 방향 표기 (상태: 제안됨, 2026-08-16)

- 위치: §3.1 정적 구조 도식 `contracts → core → seams → surfaces`
- 문제: §7 불변식 6은 `contracts ← core ← seams ← surfaces`(의존 방향)로 표기해
  같은 구조가 문서 내에서 반대 화살표로 두 번 등장한다. 도식을 의존 방향으로
  읽으면 오해를 부른다.
- 제안(택1):
  1. 도식의 화살표를 `←`로 뒤집어 의존 방향으로 통일.
  2. 도식은 유지하되 "화살표는 층의 순서이며 의존 방향은 그 역"이라는 각주 추가.
- 구현 영향: 없음 — boundarylint는 이미 의존 방향(불변식 6) 기준으로 강제 중.

## SCP-002. §5.2 코어→어댑터 command에 `approval_response` 추가 (상태: **명세 변경 요청**, 2026-08-18 갱신)

- 위치: §5.2 "코어 → 어댑터 (stdin)" 표(현재 `task`/`message`/`stop`),
  FR-ADP-02("spawn / send / events / stop의 최소 계약").
- 문제: FR-POL-05는 승인 요청이 부모 정책 레이어의 **판정**으로 이어질 것을
  요구하지만, 판정을 어댑터로 되돌릴 command가 없어 판정이 실행을 게이트할
  경로가 없다.
- **제안(단일안 — 2차 리뷰 지시로 해석 승인안 철회)**: 명세를 변경한다.
  1. §5.2 command 표에 `approval_response` 행 추가
     (payload: request_id, decision(allow|deny), reason — deny 시 필수)
  2. FR-ADP-02의 최소 공통 계약을 spawn / send / events / stop / **approval**로
     확장 명시
  3. 위 명세 변경 승인 후에만 `wire.schema.json`·codegen 반영
- 근거: 이 저장소는 기능 명세를 유일한 진실로 선언한다. §5.2 표를 그대로 둔 채
  해석 기록만으로 command를 추가하면 contracts와 명세가 다시 갈라진다.

## SCP-T28-001. FR-CLI-07 신설 — `hx --version` (상태: **승인·반영됨**, 2026-10-06, 명세 소유자 승인)

- 위치: §FR-CLI 표(현재 FR-CLI-01~06).
- 문제: 첫 공개 릴리스(JANUS-PUB, v0.1.0 제안)에서 배포 바이너리가 자기 버전·빌드
  커밋을 밝힐 수단이 없다. 현재 `hx`는 미지의 하위 명령을 오류로 거부하므로 사용자·
  운영자·버그 보고가 "어느 빌드에서 일어났는가"를 기계적으로 특정할 수 없다. 명세에
  해당 요구가 없어 FR ID 없이 구현하면 "명세 없는 기능 선제 구현 금지"에 어긋난다.
- 제안(단일안): §FR-CLI 표에 행 추가 —

  | FR-CLI-07 | `hx --version`(및 `hx version`): 빌드 시 주입된 버전 문자열·VCS 커밋·Go 버전을 stdout 한 줄로 출력하고 종료 코드 0(MUST). 주입이 없는 개발 빌드는 `devel`과 `runtime/debug.ReadBuildInfo`의 VCS 정보로 대체(SHOULD). 같은 저장소의 배포 바이너리(어댑터·보조 실행 파일 포함)는 동일 규약을 따른다(SHOULD). |

- 구현 방향(비준 후 T28): 공통 `version` 패키지(surfaces 계층, contracts·core 무접촉)에
  `-ldflags "-X …version=… -X …commit=…"` 주입 변수 + `debug.ReadBuildInfo` 폴백. 릴리스
  워크플로(태그 빌드)가 태그명·커밋을 주입. 출력은 진단이 아닌 요청된 결과이므로 stdout
  (FR-CLI-06 정합). 스키마·이벤트·정책 무변경.
- 구현 영향: surfaces/hx main 분기 1개 + 신규 패키지 + 테스트. 불변식 무접촉.
- 정정(T28 구현, 2026-10-06): seams 하위 실행 파일이 surfaces를 import할 수 없어(의존 방향 contracts ← core ← seams ← surfaces) 공통 패키지를 `core/buildinfo`(stdlib만)로 둔다. 불변식 무접촉은 동일.
- 근거: JANUS-PUB(첫 공개 릴리스 준비) — ops 판단 "배포 바이너리 자기 식별은 첫 릴리스부터
  있어야 한다"; 명세 개정은 명세 소유자 비준 사안.

## SCP-SBX04-001. FR-SBX-04 개정 — 벤더 자격증명 비취급 위협 모델 (상태: **승인·반영됨**, 2026-10-06, 명세 소유자 승인)

- 문제: 원문 FR-SBX-04("스코프를 좁힌 단기 토큰을 spawn 시 주입 MUST, 장기 자격증명 반입 금지 MUST")는 호스트가 벤더 단기 토큰을 주입하던 T15 설계를 전제했다. T23(벤더 인증 외부화) 이후 컨테이너는 벤더 자격증명을 받지 않고, 운영자 게이트웨이 접근키(정적)만 받는다 → 원문 기준 미충족.
- 결정: 선택지 A(명세를 현행 위협 모델로 개정). 선택지 B(게이트웨이 키를 단기·세션 스코프 토큰으로 발급)는 **외부 사용자 확대 시 재검토**(게이트웨이 측 지원 필요).
- 반영 문구:

원문(개정 전): `| FR-SBX-04 | 자격증명은 스코프를 좁힌 단기 토큰으로 spawn 시 주입한다(MUST). 장기 자격증명의 컨테이너 반입은 금지한다(MUST). |`

| ID | 요구사항 |
|---|---|
| FR-SBX-04 | 컨테이너는 벤더(모델 제공자) 자격증명을 받지 않는다(MUST) — 구독·API 토큰은 JANUS 밖 운영자 게이트웨이가 보유한다. 컨테이너가 받는 자격증명은 운영자 게이트웨이 접근키뿐이며, 컨테이너의 egress는 정책 allowlist(egress 핀은 allowlist 안 도메인의 해석 주소만 고정하며 목적지를 넓히지 않는다)로 제한되어 이 키가 운영자가 허용한 목적지 밖으로 나가지 않는다(MUST, FR-SBX-03). 접근키 값은 argv·spawn 메타데이터·이벤트 로그·출력 스트림에 남지 않아야 한다(MUST, FR-LOG-08). 외부 사용자 확대 시 단기·세션 스코프 게이트웨이 토큰을 재검토한다(SHOULD — SCP-SBX04-001). (world-config에 벤더 키를 넣지 않는 것은 운영자 책임이다; JANUS는 구독 OAuth env 이름을 거부한다) |
 

## SCP-D6-001. FR-CLI-08 신설 — 런타임 소켓 디렉터리 HX_RUNTIME_DIR (상태: **승인·반영됨**, 2026-10-06, 명세 소유자 승인)

- 위치: §FR-CLI 표, FR-CLI-07 다음 행.
- 문제: 런타임 Unix 소켓과 임시 디렉터리가 코드에서 `/tmp`로 고정되어 있어, 운영자가 `/tmp`를 사용할 수 없거나 다른 위치를 지정해야 하는 환경을 지원하지 못한다. macOS·Linux의 Unix 소켓 경로 길이 한계 때문에 `TMPDIR`은 대체 설정으로 사용하지 않는다.
- 제안(단일안):

  | ID | 요구사항 |
  |---|---|
  | FR-CLI-08 | 런타임 Unix 소켓·임시 디렉터리의 상위 경로는 환경 변수 HX_RUNTIME_DIR로 지정할 수 있다(SHOULD). 미지정 시 /tmp(TMPDIR 무시 — 소켓 경로 길이 한계). 지정 값이 절대 경로가 아니거나 존재하는 디렉터리가 아니거나, 그 아래 생성될 가장 긴 소켓 경로가 플랫폼 한계를 넘으면 세션 시작 전에 거부한다(MUST). 같은 저장소의 보조 실행 파일(어댑터 등)은 같은 규약을 따른다(SHOULD). |

- 구현 영향: `core/runtimedir`가 환경 변수 조회·경로/디렉터리·심볼릭 링크·플랫폼별 Unix 소켓 경로 예산을 검증하고, Claude Code 승인 소켓과 local world의 approval/audit/process broker가 이를 사용한다. `hx` 시작 경로는 claim 또는 session/start 전에 한 번 검증한다.
- 불변식 무접촉: 로그 append-only·단일 writer·파생 상태 재계산·정책 병합·계층 방향에는 변경이 없다.
